> cant i have multiple logins

● Yes, you can. The simplest way is to put the username in the remote URL. Git
  Credential Manager then stores a separate credential for each account.

  Per-repo account (recommended)

  git remote set-url origin
  https://niksbachute@github.com/niksbachute/evaluation_project.git
  git push -u origin main

  Git will ask you to sign in as niksbachute, and it saves that as its own
  entry. Shambhuraje's stored login isn't touched or replaced. Any repo whose
  remote URL has shambhu@github.com (or no username) keeps using the other
  account.

  To make Git Credential Manager send the path along with the credential, run
  this once. It makes each repo's URL pick the right login:

  git config --global credential.useHttpPath true

  Other options

  - SSH keys: Make a separate key for each account (ssh-keygen -t ed25519 -f
    ~/.ssh/id_nikita). Add each public key to its GitHub account. Then add a
    Host github-nikita entry in ~/.ssh/config that points at that key, and use
    git@github-nikita:niksbachute/evaluation_project.git as the remote. This is
    the most robust choice if you juggle accounts often.
  - GitHub CLI: gh auth login can hold several accounts, and gh auth switch
    changes between them. This only helps if you use gh for the git credentials
    (gh auth setup-git).

  The local user.name and user.email only label your commits. The login is a
  separate thing, and the URL username is what picks which one gets used.
